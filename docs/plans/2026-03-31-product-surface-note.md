# Product Surface Note

## Problem

The current product surface had three strong stories but no clean newcomer map:

- the docs/front door story,
- the operator shell story,
- the decision/review story.

That made the app feel like several good rooms without a hallway.

## Current Operator Map

The current operator map should now be read as:

1. **Quick Launch** starts work.
2. **Task Center** follows work and clears manual blockers.
3. **Flow Workshop** refines work after you learn from a run.
4. **Review Board** compares governed evidence before a decision.

## Why This Note Exists

This note separates three layers that are easy to confuse:

- **surface role**
- **truth owner**
- **route-specific product ambition**

### Surface role

- Quick Launch = start
- Task Center = track and unblock
- Flow Workshop = refine
- Review Board = decide

### Truth owner

- workflow runs live in the workflow ledger
- command runs live in the automation command ledger
- governed proof lives in the governed run bundle
- command-tower data remains runtime projection rather than the primary truth

### Route-specific ambition

- Route A may later make Review Board the dominant public product surface
- Route B may later make stress/load/synthetic surfaces the dominant public
  product surface

This round deliberately stopped short of that larger route-dependent choice.

## Product Surface Rules For The Next Round

- keep onboarding and help outcome-led
- keep Review Board explanation tied to existing evidence prerequisites
- keep Manual Gate explanatory, not auto-decision-making
- keep AI in reading/suggestion/summarization roles
- keep MCP framed as a connection/workspace layer
